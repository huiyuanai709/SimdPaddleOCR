# SimdPaddleOCR — RK3399（OrangePi 4 LTS）CPU / Vulkan

实测机：OrangePi 4 LTS，Rockchip RK3399（2× Cortex-A72 1.8 GHz + 4× Cortex-A53 1.416 GHz，共 6 核），Mali-T860 MP4（panfrost），4 GB LPDDR4，eMMC。Ubuntu 22.04.1，内核 5.18.5-rk3399，cpufreq `ondemand`。被动散热（无散热片 / 风扇）。.NET SDK 10.0.401（运行时 10.0.12，`dotnet-install.sh --channel 10.0` 装在 `/root/.dotnet`），在板子上 `dotnet build -c Release` 编译 `test/Sdcb.SimdPaddleOCR.Tests`（首次编译含 restore 约 7.5 分钟）。`--benchmark --benchmark-kind simd --warmup 1`，同一 `dataset/` 100 张变尺寸图，n=99。本表 `f3dc70a`。

**结论：这块板子上只能用 CPU。Mali-T860 是 Midgard（v5），Mesa PanVK 不支持（[Mesa Panfrost 支持表](https://docs.mesa3d.org/drivers/panfrost.html) 中 T860 只有 GLES / GL / OpenCL），系统里唯一的 Vulkan 设备是 llvmpipe（`PHYSICAL_DEVICE_TYPE_CPU`），`VkDevice.Create` 会跳过它，`--engine vulkan` 静默回退到 CPU。CPU 三档精度与 Windows 基线完全一致；4 线程 median：tiny 1.24 s，small 5.9 s，medium 24.8 s。持续负载下 A72 一直卡在 70 °C 降频点，medium 平均只有 872 MHz，散热是这块板子最大的性能变量。**

## 设备能力

| 项            | 值                                                                                                                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| CPU           | policy0：CPU0–3 Cortex-A53，最高 1416 MHz；policy4：CPU4–5 Cortex-A72，最高 1800 MHz。`Environment.ProcessorCount` = 6                                                                     |
| SIMD          | AArch64 AdvSimd（NEON），没有 SVE / dotprod / fp16 算术。走库的 AdvSimd 内核                                                                                                               |
| GPU           | Mali-T860 MP4（`shader_present=0xf`），panfrost 1.2.0，devfreq 200–800 MHz                                                                                                                 |
| Vulkan 加载器 | `libvulkan1` 1.3.204                                                                                                                                                                       |
| Vulkan ICD    | 装 `mesa-vulkan-drivers`（23.2.1）后只有 broadcom / freedreno / radeon / virtio / lvp，**没有 panfrost ICD**；`vulkaninfo` 只枚举到 `llvmpipe (LLVM 15.0.7, 128 bits)`，`deviceType` = CPU |
| 温控          | `cpu-thermal` trip 70 / 75 / 95 °C；空闲约 55 °C                                                                                                                                           |

### 为什么没有 Vulkan

- PanVK 只覆盖 Bifrost（v6 / v7）及以后；Midgard（T760 / T820 / T830 / T860 / T880 都是 v5）在 Mesa 里只有 GLES 3.1 / GL 3.1 / OpenCL 3.0。换更新的 Mesa 也不会有。
- Rockchip 的闭源 libmali（midgard-t86x）需要换成 mali kbase 内核驱动，本次没有尝试。
- llvmpipe 是 CPU 上的软件 Vulkan，即使不过滤也只会比原生 AdvSimd 内核慢。`VkDevice.Create` 第二轮挑选显式排除 `PhysDeviceCpu`，抛出 `PlatformNotSupportedException`，`GpuBackend` 探测失败后会话走 CPU，没有任何报错输出。

实测 `--engine vulkan`：日志 `backend=vulkan`，但算子统计是 CPU 的 `Conv` / `MatMul`，精度与 CPU 完全一致（tiny 742 / 2.37%）；median 1446 ms 对 CPU 1244 ms 是热状态不同（大核平均 1058 vs 1513 MHz），不是 GPU 开销。

| ------ | -----------: | ------: | ------: | -------: | -----------: | -----------: |
| tiny   |       1244.5 |  1234.8 |  1557.0 |   524 MB |     1513 MHz |   2 分 17 秒 |
| small  |       5907.2 |  5767.6 |  7347.7 |   708 MB |     1227 MHz |   9 分 52 秒 |
| medium |      24777.7 | 24328.8 | 31475.2 |  1.24 GB |      872 MHz |  40 分 50 秒 |

大核平均频率由每 2 s 采样 `policy4/scaling_cur_freq` 得出；三档几乎所有采样点都在 1.8 GHz 以下，温度均值 69.5–69.7 °C、最高 71.7 °C，也就是一直贴着 70 °C 的第一个 trip 点。小核基本保持 1416 MHz。

参照（同一数据集、4 workers、CPU median）：

| 设备                                                           |   tiny |  small |  medium |
| -------------------------------------------------------------- | -----: | -----: | ------: |
| Ryzen 7 5800X（[perf.md](perf.md)）                            |   53.8 |  190.2 |   673.4 |
| 骁龙 8 Gen 3（[vulkan-8gen3.md](vulkan-8gen3.md)，热状态 2–3） | 约 219 | 约 811 | 约 3294 |
| RK3399（本文，被动散热）                                       | 1244.5 | 5907.2 | 24777.7 |

RK3399 约为 5800X 的 1/23（tiny）到 1/37（medium）。模型越大差距越大，主要因为降频越重（medium 大核只剩标称的 48%）。

## 线程数（tiny）

| workers | median ms |    p95 | 峰值 RSS | 大核平均频率 |
| ------: | --------: | -----: | -------: | -----------: |
|       1 |    1517.6 | 1964.4 |   509 MB |     1081 MHz |
|       2 |    1411.3 | 1750.0 |   521 MB |     1003 MHz |
|       4 |    1244.5 | 1557.0 |   524 MB |     1513 MHz |
|       6 |    1318.7 | 1648.5 |   532 MB |      956 MHz |

- 4 workers 那一轮是开机后第一次满载，大核频率明显更高，其余三轮在连续 1 小时 medium 之后、都已热透（约 1000 MHz），所以 4 与其它行不能直接比；1 / 2 / 6 三行之间热状态接近。
- 热透之后 6 workers 比 2 workers 只快约 7%，1 → 6 也只有 1.15×。4 个 A53 帮得上的有限，且线程越多发热越大、大核频率越低。被动散热下 2–4 workers 已经足够。

## 建议

- **加散热。** 所有数字都是热降频后的。RK3399 加散热片 + 风扇后大核可以长期保持 1.8 GHz，small / medium 预计能有明显提升（本次未测）。
- 选 tiny 或 small。medium 单图 25 s 左右，且峰值 1.24 GB（4 GB 内存够用，但没有余量再跑别的大模型）。
- 不要在这块板子上指定 `OcrBackend.Vulkan`：不会出错，但也没有任何 GPU 加速；`Auto` 同样走 CPU。

## 复现

```bash
# 板子上
curl -sSL https://dot.net/v1/dotnet-install.sh -o dotnet-install.sh
bash dotnet-install.sh --channel 10.0 --install-dir /root/.dotnet
apt-get install -y mesa-vulkan-drivers vulkan-tools   # 只为确认 Vulkan 设备，可选
vulkaninfo --summary                                  # 只会看到 llvmpipe

# 源码 + models/ + dataset/ 拷到板子后
/root/.dotnet/dotnet build test/Sdcb.SimdPaddleOCR.Tests -c Release
/root/.dotnet/dotnet test/Sdcb.SimdPaddleOCR.Tests/bin/Release/net10.0/Sdcb.SimdPaddleOCR.Tests.dll \
  --benchmark --benchmark-kind simd --engine sharp|vulkan --workers 4 \
  --model tiny|small|medium --input dataset --warmup 1 --out bench-out/x.json

# 温度 / 大核频率采样
while true; do echo "$(date +%s) $(cat /sys/class/thermal/thermal_zone0/temp) \
  $(cat /sys/devices/system/cpu/cpufreq/policy4/scaling_cur_freq)"; sleep 2; done
```

JSON / 日志 / 采样：`bench-out/rk3399/r1-{sharp,vulkan}-{tiny,small,medium}-w{1,2,4,6}.{json,log,mon}`（gitignored）。
